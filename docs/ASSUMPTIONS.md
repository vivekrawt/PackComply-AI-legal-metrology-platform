# Assumptions Register

Every point below is an engineering assumption made where the PRD left an open decision or was
ambiguous. Each is deliberately **small, reversible and configurable** — none invents legal content.

| # | Area | Assumption | Reversal path |
|---|------|-----------|---------------|
| A1 | Legal parameters | All seeded rule versions (declaration presence/format families, DEMO Rule 7 thresholds of 2 mm/4 mm, required MRP phrase, permitted unit list) are **placeholders flagged `REQUIRES_LEGAL_APPROVAL`**; structure follows the PRD's declaration catalogue, values are not certified statutory data | Rule admin edits/publishes certified versions via the governance workflow; no code change |
| A2 | Finalization policy | The `user` role may finalize (PRD says "policy based"); overrides of `high`-severity failed findings need independent second-level approval from `admin`/`super_admin` | `finalization_policy` config item (`userCanFinalize`) |
| A2b | Role model | The PRD's six role archetypes are collapsed to three operational roles — `user` (does the work), `admin` (reviews it) and `super_admin` (write + delete). Read-only archetypes (analyst, auditor) map onto `user` and `admin`; rule administration and system administration both sit with `super_admin`. Reversible: the matrix is one file (`server/src/modules/auth/permissions.ts`) and legacy names are remapped by migration `003` | `ROLE_PERMISSIONS` |
| A2c | Deletion semantics | "Delete" is a soft delete with a mandatory reason, held only by `super_admin`. Rows and evidence hashes are retained so the hash-chained audit log and any issued report stay verifiable; deleted inspections are restorable. Published rule versions are never deletable; user accounts are offboarded and anonymised rather than dropped | `deleted_at`/`deleted_by`/`deleted_reason` columns, migration `003` |
| A3 | Severity levels | Demo severity per rule (e.g. missing MRP/quantity/entity/care/origin = high) is policy config, not legal determination | Edit rule version `outcome.severityOnFail` |
| A4 | Tenant model | Single organization ("Demo Legal Metrology Directorate", fictional) with state/district/office scope columns; multi-tenant = separate org rows | Org table already hierarchical |
| A5 | Auth | Local accounts (scrypt) with MFA-ready schema; OIDC/SAML SSO is an adapter boundary, not wired (no IdP available in a free local build) | Implement adapter against chosen IdP |
| A6 | E-commerce capture | **No automated crawling at all** in MVP (safe default per ECM-07); URL + officer-entered structured fields + screenshot uploads are the evidence path; the country-of-origin filter test is a manual record | Add capture adapters behind the domain-policy config later |
| A7 | Checklists | Default required views per inspection type (physical: front+back; warehouse: +side; complaint: front; ecommerce: listing) | `checklists` config item |
| A8 | Providers | OCR now defaults to the REAL self-hosted tesseract.js adapter (eng+hin), with language data committed to `server/assets/tessdata` so a fresh clone works offline. Image-quality, layout, extraction and font-measurement remain deterministic demo providers, labeled `isMock` everywhere they surface. The adapter is unbenchmarked against the PRD acceptance corpus | `PROVIDER_*` env selects any implementation; benchmark before pilot |
| A19 | Demo label images | Seed evidence is real, legible PNG artwork of clearly fictional products (invented brands, `.example` domains, a "SYNTHETIC DEMO LABEL — NOT FOR ENFORCEMENT USE" footer), generated by `scripts/generate-demo-labels.mjs` and committed so seeding needs no browser. Two labels are deliberately non-compliant (retail price without the tax-inclusive wording; no consumer-care details) and the demo listing price deliberately contradicts its pack, to exercise real findings | Regenerate the script's `LABELS` array |
| A20 | Demo calibration | The seeded known-dimension calibration (0.11 mm/px) states the synthetic 1100 px label represents a 120 mm package face. It is a demo input, not a measurement of a real package; the second demo pack has no calibration so the same rule returns Not Assessable | Officers record real calibrations per asset |
| A9 | Font measurement | Mock font provider reports pixel heights from OCR-region geometry (nominal 1200 px image height); mm conversion happens only in the engine with calibration | Real provider measures actual glyphs; engine unchanged |
| A10 | Calibration | Officer-entered mm-per-pixel (method + uncertainty) stands in for marker auto-detection; plausibility-bounded | Marker detection adds a `marker` calibration row |
| A11 | Storage | SQLite + local filesystem stand in for PostgreSQL + object storage; SQL kept portable, store behind `ObjectStore` interface | Swap drivers at deployment |
| A12 | Jobs | In-process DB-backed worker (idempotent, retries, dead-letter) instead of an external queue | Same job contract on a queue service |
| A13 | Signatures | Report "signing" = SHA-256 of canonical snapshot + verification endpoint; digital e-sign/QR is an adapter point (RPT-05 Should) | Integrate approved e-sign provider |
| A14 | Retention | Legal-hold flag blocks deletion; retention periods are config with **no automated disposal job** (disposal authority is an open PRD decision) | Add scheduled disposal honoring policy |
| A15 | Offline | Encrypted offline drafts implemented: AES-GCM via WebCrypto with a **non-extractable CryptoKey stored in IndexedDB** — data at rest is opaque to profile inspection, but script on the same origin can still use (not read) the key; this is not a substitute for device security policy/MDM. Create-only drafts (no offline edits of server records) so material conflicts cannot arise; sync is idempotent via `clientRef` and failures surface explicitly | Server-wrapped keys / MDM-backed storage when a device profile is approved (open PRD decision) |
| A16 | Hindi | Mock OCR emits Devanagari lines and normalizers handle Devanagari digits/units; UI Hindi dictionary is partial | Extend dictionaries + benchmark real OCR |
| A17 | Demo emails | Demo accounts use the reserved `.example` TLD to avoid resembling real government addresses | Seed data only |
| A18 | Improvement notices | Notice eligibility (first procedural non-compliance, repeat/fraud exclusions) is an officer decision; the system records the workflow only | Matches PRD's officer-authority principle |
